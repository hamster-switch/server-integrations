# sub2api 补丁功能与页面升级

## Goal

在现有 sub2api Hamster Switch YAML 补丁基础上，完善“配置订阅”、“配置订阅教程”、YAML 生成/维护、导入 Hamster Switch 及订阅生命周期体验。

## Confirmed Facts

- 上游 sub2api 的普通用户 API Key 列表和单项接口均返回完整明文 `key`；用户页仅通过 `maskApiKey` 在视觉上显示首 6 位和末 4 位，复制操作直接使用已经进入浏览器内存的完整值。
- 上游 sub2api 的管理员用户密钥列表同样通过 DTO 返回完整明文，管理员弹窗只在显示层截取首尾字符，因此不能把现有页面行为视为服务端脱敏。
- API Key 以可恢复明文写入 `api_keys.key`；现有代码没有独立的“查看密钥”端点，也没有针对查看/复制动作的专门审计事件。
- 常规访问日志记录 method、path、状态码、耗时、客户端 IP 及必要的账号/平台/模型标识，不记录请求头或响应体；网关错误记录保存 API Key ID 和最多 8 字符前缀，不保存完整有效密钥。
- 删除审计是例外：`deleted_api_key_audits` 会保存被删除 API Key 的完整明文，以便后续按失效密钥归因错误。
- 公共 `/health` 仅返回静态 `status=ok`，并被访问日志跳过；它不验证数据库/Redis，也不涉及或返回 API Key。管理员另有日志采集健康指标端点，但只返回采集器状态。

- 现有补丁已有独立“订阅管理”页面、创建订阅、复制 URL、使用教程、编辑/下载 YAML、专用 API Key 与订阅下载端点。
- 订阅 URL 与专用 API Key 生命周期绑定；上游账号密钥不得导出。
- 当前安装方式修改 sub2api 源码树，之后需要重建和重启。
- 新的生产安装/检查/更新路径只面向 Linux 服务器。
- 当前功能仍处于开发阶段，没有需要保护的正式用户或已部署 Hamster 刷新链路，因此允许对旧订阅 URL 做破坏性迁移。

## Requirements

- Hamster 订阅管理沿用 sub2api 现有 API Key 脱敏形式：后端可向已登录且通过所有权校验的页面返回完整订阅专用 API Key 和完整 YAML，前端默认只对密钥做首 6 位、末 4 位的视觉脱敏。
- 复制密钥、复制订阅 URL、复制 YAML 和下载 YAML 直接使用已返回到页面的完整值，不新增显式揭示端点、二次认证、查看限流或专门的查看/复制审计事件。
- 最终订阅 YAML 保留完整专用客户端 API Key；不得把上游账号密钥加入模板上下文、管理接口或 YAML。
- 服务访问日志、错误记录和健康检查沿用 sub2api 既有字段与脱敏习惯，本轮不建立跨项目统一安全日志契约，也不额外把完整订阅凭据写入新日志字段。
- 将“订阅管理”统一调整为“配置订阅”，保留并明确现有创建/列表能力；侧边栏、路由标题、页面标题、空状态和相关操作文案使用同一名称。
- 将“使用订阅”入口改名为“配置订阅教程”，点击后进入步骤化同名二级教程，支持通用内容、管理员定制内容及步骤图片。
- 教程采用稳定步骤 ID 的通用底稿与站点覆盖层；管理员可编辑文案、替换图片、隐藏/排序通用步骤并新增站点步骤。
- 教程图片支持通用 Release 资产、本站上传和管理员外链三种来源。
- 外链由服务器执行 SSRF 防护与图片校验后代理缓存，浏览器不直接访问第三方源站。
- YAML 由服务器真实 API Key、外部项目端点、模型与展示元数据生成；字段契约与 Hamster Switch 解析器兼容。
- 加入导入 Hamster Switch、禁用、编辑、删除操作，并明确它们与 API Key 生命周期的关系。
- 禁用是可恢复操作：在同一事务中把订阅标记为禁用并停用其全部专用 API Key，但不重新生成、不删除凭据，也不改变订阅 URL；禁用期间原 URL 返回 `410 Gone` 和明确的已禁用错误。
- 重新启用时在同一事务中恢复订阅及原专用 API Key，原 URL 和原 YAML 中的凭据继续有效，用户无需重新导入 Hamster Switch。
- 删除是用户侧不可恢复操作。确认后事务化删除订阅并撤销/删除其全部专用 API Key；原订阅 URL 永久失效并返回 `404`，再次创建必须生成新 URL 和新 API Key。数据库内部可使用软删除维持关联完整性，但不提供回收站或恢复入口。
- 删除弹窗中文正文固定为 `确定要删除'{name}'吗？此操作无法撤销。`，其中 `{name}` 使用订阅名称；标题、取消/删除按钮、危险色、成功提示、失败提示、关闭和列表刷新逻辑复用 sub2api 现有 API Key 删除流程及 `ConfirmDialog`/`BaseDialog` 体系。
- 删除请求失败时保留当前弹窗和列表数据并展示原项目风格的错误提示；成功后关闭弹窗、提示成功并刷新列表，不做前端假删除。
- “导入 Hamster Switch”仅发起深链并预填桌面端“从 URL 导入”页面，不把网页点击视为已导入成功。
- 订阅采用持久化实体与稳定 URL；普通编辑不改变 URL，刷新原 URL 返回当前已发布配置。
- 升级后不迁移按 API Key 名称临时聚合的旧订阅，也不兼容旧版签名 URL；新下载端点只解析持久化“配置订阅”实体签发的新 URL，旧 URL 直接失效。
- 升级脚本不静默删除旧开发期专用 API Key；开发环境如需清理，由开发者确认后手动删除或重置开发数据库。
- 分组增删与对应专用 API Key 的创建/撤销必须事务化；禁用与删除分别具有独立语义。
- 管理员维护面板只负责允许定制的教程/YAML 展示或模板字段，不得绕过安全与协议校验。
- 管理员可直接编辑完整原始 YAML 模板；模板通过受限变量注入运行时订阅数据，不得执行任意代码。
- 受限 DSL 仅开放登记变量、providers/models 循环和简单条件，不得读取环境变量、文件、网络或调用函数。
- 模板只开放规范化安全上下文；可使用该订阅专用客户端 API Key，但不得访问上游账号密钥或任意数据库/环境字段。
- 模板硬错误不可绕过；允许保存无效草稿，但禁止发布并替换当前有效版本。
- 非关键警告允许管理员在查看详情后确认发布，并记录确认人、时间和警告集合。
- 通用教程/YAML 更新必须经管理员确认，并在站点存在定制内容时避免原地覆盖。

## Dependencies

- 依赖“远程补丁与内容发布机制”定义通用内容版本和覆盖契约。
- 依赖“Hamster Switch 订阅深链导入契约”定义导入按钮行为。

## Acceptance Criteria

- [ ] 每个页面操作均有权限、后端端点、状态变化与失败反馈定义。
- [ ] YAML 不泄露上游账号密钥，导出的客户端密钥可独立禁用/删除。
- [ ] 完整模板有草稿、预览、校验、发布版本和回滚流程；无效模板不能替换当前有效版本。
- [ ] 通用教程更新不会覆盖管理员定制内容，管理员内容损坏时可回退。
- [ ] 同一步骤发生远程与站点修改冲突时逐项提示管理员处理，不自动合并。
- [ ] 教程/YAML 更新提供版本与差异预览，管理员拒绝更新时维持当前站点内容。
- [ ] 导入 Hamster Switch 前能预览目标订阅且不会在网页日志中暴露密钥。
- [ ] 编辑成功后原 URL 返回完整新版本；编辑失败时原 URL 继续返回完整旧版本。
- [ ] 管理页面默认视觉脱敏，复制或下载所得内容包含可用的完整订阅专用 API Key，且不包含上游账号密钥。
- [ ] 禁用后原 URL 返回 `410 Gone` 且专用 API Key 不可调用；重新启用后原 URL、原 API Key 和 Hamster 刷新订阅能力全部恢复。
- [ ] 删除弹窗显示准确订阅名称和不可撤销文案；删除成功后原 URL 返回 `404`、全部专用 API Key 不可调用且页面不存在恢复入口。
- [ ] 页面唯一业务名称为“配置订阅”，教程入口和二级页标题为“配置订阅教程”，不存在遗留的“订阅管理”“我的订阅”或“使用订阅”用户文案。
- [ ] 旧版签名 URL 在升级后不可下载配置；新页面只展示和管理持久化实体签发的新 URL，升级过程不静默删除旧开发数据。
